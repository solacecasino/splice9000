# splice9000 0.0.1

The first release of splice9000: a bare, modular video editor. Drop clips
in, cut them on one timeline, watch them with sound, export a video. Every
panel can be moved, resized, added or removed, the way foobar2000 lets you
rearrange its window.

**Download:** `splice9000-0.0.1-macos-universal.zip` (6.5 MB), for Apple
Silicon and Intel Macs on macOS 11 or later. Unzip it and move
splice9000.app to Applications. The first time, **right-click → Open**: the
app isn't signed with an Apple developer certificate, so macOS asks once.
You also need ffmpeg (`brew install ffmpeg`).

## What's in it

- **Editing.** One video track: split at the playhead (`s`), trim by
  dragging a clip's edge, move clips by dragging, delete, undo and redo.
  Trims snap to the source's frames, the playhead to the edit's.
- **Preview with sound.** Frame-accurate scrubbing, and playback that the
  sound keeps in time: the picture follows the audio clock, so the two can't
  drift. Clips without sound play silence of the right length. `m` mutes.
- **Export.** The whole edit in one ffmpeg run, with clips of different
  sizes, frame rates and audio joined correctly. Size, frame rate, codec and
  quality are set in `settings.toml` (default: the first clip's size and
  rate, H.264, CRF 20).
- **A layout you arrange.** Panels sit edge to edge, divided by a single
  line you drag to resize. Drag a panel by its header to move it beside
  another or swap the two; right-click a header to add, replace or remove
  one; View → Panels shows or hides any panel. Saved to `layout.toml`.
- **Menus.** The system menu bar on macOS: File, Edit, View, Playback,
  Window, Help, showing your own shortcuts.
- **Plain-file settings.** `settings.toml`, `keys.toml` and `layout.toml`
  in one folder (⌘,), each with commented examples. Saved changes apply at
  once. A file with a mistake falls back to the defaults, and the Log panel
  says what's wrong.
- **Your work kept.** The edit is saved as you go and comes back after a
  restart or a crash. ⌘S saves a `.splice` project file to keep.

## Measured

On an Apple Silicon MacBook, Retina screen, release build:

| | |
|---|---|
| Download / app | 6.5 MB / 6.0 MB per architecture (ffmpeg not included) |
| Memory, fresh start | 54 MB |
| CPU when idle | 0.0% |
| Playing 1080p in a ~1300×740 preview | splice9000 20–23% of one core, ffmpeg 38% |
| Sound | no measurable extra CPU |
| Drawing a video frame | 2.5–5 ms |
| Showing one frame when scrubbing | about 95 ms |
| Export, 15 s of 1080p from 3 clips | 2.0 s (7.5× real time) |

What didn't work, or was wrong along the way:

- Hardware decoding makes a single scrub frame slower (260 ms against
  95 ms): starting the decoder costs more than one frame. Scrubbing uses
  software decoding; playback uses the hardware.
- The window was first drawn into one shared buffer, as in Folio, and macOS
  sometimes showed a video frame half drawn. There are now two buffers that
  take turns (about 16 MB more on this screen).
- An early figure of 8% CPU while playing came from `ps`'s decaying %CPU
  average. Measured from CPU time, it's 20–23%.

## Tested

- 26 unit tests, including a real export through ffmpeg (mixed sizes, frame
  rates and clips without sound) and dragging a panel by its header with
  real pointer input fed through egui.
- By script on this Mac: playback across cuts with sound, splitting, live
  reload of settings and layout, light mode, the menu bar, a fresh start
  with no config, and the packaged app opened through Finder's route (finds
  Homebrew's ffmpeg without a shell PATH).

Not tested by hand: dragging with a real mouse, clicking menu items, and the
Import and Export dialogs.

## Known limits

- One video track. No transitions, titles, effects or speed changes.
- Sound plays only while playing, not while scrubbing.
- No thumbnails or waveforms on the timeline.
- Mac only for now (Windows and Linux build from the same code but haven't
  been run), and the app isn't notarized.

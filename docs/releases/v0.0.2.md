# splice9000 0.0.2

splice9000 now comes for Windows and Linux too, built and tested on every
system by GitHub Actions. Nothing changed for Mac users except the version.

## Downloads

| | |
|---|---|
| `splice9000-0.0.2-macos-universal.zip` (6.5 MB) | Apple Silicon and Intel Macs, macOS 11 or later |
| `splice9000-0.0.2-windows-x64.zip` (3.2 MB) | Windows on Intel and AMD |
| `splice9000-0.0.2-windows-arm64.zip` (2.8 MB) | Windows on Arm |
| `splice9000-0.0.2-linux-x64.tar.gz` (5.4 MB) | Linux on Intel and AMD (glibc 2.35 or later) |
| `splice9000-0.0.2-linux-arm64.tar.gz` (5.0 MB) | Linux on Arm |

All of them need [ffmpeg](https://ffmpeg.org): `brew install ffmpeg` on a
Mac, `winget install ffmpeg` on Windows, `sudo apt install ffmpeg` on
Debian and Ubuntu.

- **Mac:** unzip, move splice9000.app to Applications, and the first time
  **right-click → Open** (the app isn't notarized).
- **Windows:** unzip anywhere and run `splice9000.exe`. Windows may warn
  about an unknown publisher the first time (the app isn't signed).
- **Linux:** unpack, then `./install.sh` adds splice9000 to your app menu
  with its icon (`./install.sh --remove` takes it out). Linux needs ALSA
  for sound and libxkbcommon-x11, which desktop systems already have.

## What's new

- **Windows and Linux.** On both, the menus (File, Edit, View, Playback,
  Help) are drawn in the window's top strip, with Exit at the bottom of
  File.
- **Built and tested on every push.** macOS (and the universal app's Intel
  half on an Intel Mac), Windows x64 and Arm, Linux x64 and Arm. Each
  machine runs the tests, including a real export through ffmpeg, then
  unpacks its download and starts it with a sample edit loaded.
- `splice9000 --version`.
- `scripts/sample.py` makes two sample clips and a session to try the app
  with.

## Fixed

- **Windows and Linux: most of the window stayed blank.** The first frame
  is drawn while the window is still hidden, and Windows and X11 drop it.
  Only the parts that changed were sent after that, so only the video area
  showed. Now the whole picture is sent until one frame has reached the
  visible window. The CI screenshots found this before any release had it.
- No console window opens behind splice9000 on Windows.

## Tested

- On GitHub Actions, for every download: 26 unit tests (including a real
  export and dragging a panel by its header), `--version` from the unpacked
  download, and a screenshot of the app running with a sample edit. Windows
  Arm is the exception for screenshots: its runner sits on Windows' setup
  screen.
- Linux: `install.sh` adds a valid app menu entry and icon that start the
  app, and `--remove` takes them out.
- By hand on a Mac, as in 0.0.1.

Not tested by a person yet: the Windows and Linux builds (only by CI),
clicking menu items, and the Import and Export dialogs.

## Known limits

- Windows doesn't notice changes to the config files while running; they
  apply the next time splice9000 starts. (macOS and Linux apply them at
  once.)
- One video track. No transitions, titles, effects or speed changes.
- Sound plays only while playing, not while scrubbing.
- Nothing is signed with a paid certificate, so macOS and Windows ask once.

## Compatibility

Settings, keys, layouts, sessions and `.splice` files from 0.0.1 work as
they are.

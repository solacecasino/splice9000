# splice9000 0.0.3

Playback starts cleanly: pressing play no longer stutters.

**Downloads:** macOS (universal), Windows (x64 and Arm) and Linux (x64 and
Arm), as in 0.0.2. All of them need [ffmpeg](https://ffmpeg.org). Install
steps are in the [README](https://github.com/solacecasino/splice9000#installing).

## Fixed

- **A stutter every time you pressed play.** The sound started its clock at
  once, but the video decoder took about half a second to start, so the
  first 0.4–0.5 s of frames counted as late and were skipped: a freeze, then
  a jump. The clock now starts with the first picture, so playback begins on
  exactly the frame you paused on, with the sound in step.
- **A flicker when pausing.** A frame from just past the pause point could
  land after you pressed pause, then the picture jumped back. Frames that
  arrive after pausing are now ignored.

## Changed

- **Software video decoding by default.** The system's hardware decoder took
  420–590 ms to show the first frame after pressing play, against 125–190
  ms in software, and saved only about 6 points of CPU while playing (38%
  against 44% for 1080p H.264). Turn it back on with `hwaccel = true` under
  `[preview]` in settings.toml.
- The next clip's decoder starts once the current clip's first picture is
  showing, so the two don't compete when you press play.

## Measured

On an Apple Silicon MacBook, six pause/play cycles through a three-clip edit:

| | 0.0.2 | 0.0.3 |
|---|---|---|
| Pressing play until the first frame | 560–640 ms | 90–210 ms (about 320 ms the first time, opening the sound device) |
| Picture skipped when playback starts | 0.4–0.5 s | none |
| Time between frames while playing (30 fps) | — | 35 ms median, 39 ms at the 95th percentile, 45 ms worst |

## Tested

- The timings above with simulated key presses, on this Mac. Pausing and
  playing by hand hasn't been timed.
- CI on every download, as in 0.0.2: 26 unit tests including a real export,
  `--version` from the unpacked download, and a screenshot of the app
  running with a sample edit (all but Windows Arm).

## Compatibility

Everything from 0.0.2 works as it is, and splice9000 never rewrites your
files. That includes `settings.toml`: the one written by 0.0.1 or 0.0.2
says `hwaccel = true`, so it keeps hardware decoding. The skipping is fixed
either way, but for the faster start change that line to `hwaccel = false`
(⌘, opens the folder), or delete it to use the new default.
